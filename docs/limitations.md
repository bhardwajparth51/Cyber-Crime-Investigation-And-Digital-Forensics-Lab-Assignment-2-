# Investigation Limitations and Scope Boundaries

1. **Synthetic Dataset Only:** Every email, header, IP address, endpoint event, authentication record, bank account, and wallet identifier is fictional. The investigation demonstrates analytical methodology rather than documenting a real-world breach.
2. **Embedded Authentication Headers vs. Live Verification:** `PHISH-01` through `PHISH-03` contain embedded synthetic `Authentication-Results` headers (`simulated_fail`, `simulated_pass`, etc.). Offline analysis cannot verify cryptographic DKIM signatures against live DNS keys.
3. **Harmless Malware Telemetry Simulation:** No executable malware binary exists in this repository. Behavioral classification (`Simulated Trojan`) relies on predefined synthetic JSON events and a benign Base64 text fixture rather than sandbox detonation or memory forensics.
4. **Correlation vs. Legal Causation:** Timestamp correlation links `invoice_viewer.exe` telemetry (`09:15:15Z`) to external login `SES-9941-HYDRA` (`09:22:30Z`), but in a real investigation proving credential theft causation would require volatile memory acquisition and browser credential store forensics.
5. **Attribution Uncertainty:** Observed IP addresses (`203.0.113.95`), mule accounts (`MULE_ACC_01`–`04`), and fictional crypto wallets (`HYDRA-SIM-WALLET-*`) identify technical and financial conduits, not the identity or culpability of specific natural persons. Lawful KYC records, ISP subscriber logs, and judicial process would be required in an actual case.
6. **External Service Restrictions:** Optional external aids (VirusTotal, AbuseIPDB, MXToolbox, ICANN Lookup) are excluded from automated execution so the repository stays deterministic, offline-reproducible, and compliant with evidence confidentiality rules.
